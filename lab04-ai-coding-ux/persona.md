# Persona: สมชาย มั่นคงสต็อก (Somchai Munkongstock)

## ข้อมูลทั่วไป:
- **อายุ:** 38 ปี
- **ตำแหน่ง:** เจ้าหน้าที่คลังสินค้าอาวุโส (Senior Warehouse Officer)
- **ประสบการณ์:** 5 ปีในการจัดการคลังสินค้า (ใช้ Excel/Spreadsheets บันทึกข้อมูลเป็นหลัก)
- **อุปกรณ์หลัก:** คอมพิวเตอร์ตั้งโต๊ะ PC (Windows, จอ 21.5 นิ้ว) ประจำโต๊ะคลังสินค้า และแท็บเล็ต/สมาร์ตโฟน Android ตรวจเช็กของหน้างาน
- **ทักษะเทคโนโลยี (1-5):** ระดับ 2 (ใช้โปรแกรมพื้นฐาน งานเอกสาร พิมพ์งาน และ Spreadsheet ได้ แต่ไม่ถนัดคำสั่งลัดซับซ้อน กลัวการกดปุ่มผิดแล้วข้อมูลหาย)

## Quote ที่บ่งบอกตัวตน:
> *"ผมแค่อยากคีย์ของเข้าออกให้ไวและถูกต้อง กลัวที่สุดคือคีย์ผิดช่องแล้วมารู้ทีหลังว่ายอดสต็อกไม่ตรง ทำให้ต้องเสียเวลาตามแก้ย้อนหลังทั้งวัน"*

## Goals:
1. บันทึกรับเข้าและเบิกจ่ายสินค้าได้สะดวกรวดเร็ว โดยมีระบบช่วยตรวจสอบความถูกต้องทันที และแยกชนิดสินค้าระหว่างสินค้าจับต้องได้กับสินค้าดิจิทัลได้อย่างไม่สับสน
2. ตรวจสอบสถานะภาพรวมของสต็อกและสินค้าใกล้หมด (Low Stock) ได้ทันทีเมื่อเปิดหน้าจอ Dashboard โดยไม่ต้องคำนวณสูตรหรือฟิลเตอร์ข้อมูลเอง

## Frustrations:
1. **ช่องกรอกข้อมูลในระบบเดิมใช้แต่ Placeholder:** พอเริ่มพิมพ์ข้อความ ตัวหนังสือตัวอย่างก็หายไป ทำให้จำไม่ได้ว่ากำลังกรอกฟิลด์อะไร (เช่น สับสนระหว่าง รหัสสินค้า กับ บาร์โค้ด หรือ ราคาทุน กับ ราคาขาย)
2. **ปัญหาสินค้าสองประเภท (กายภาพ vs ดิจิทัล) ปะปนกัน:** สินค้าดิจิทัล (เช่น E-Book คู่มือ, รหัสคีย์ลิขสิทธิ์) ไม่มีจำนวนนับสต็อก แต่ระบบเดิมบังคับให้ใส่จำนวนชิ้น ทำให้พนักงานคลังสับสนและยอดรวมในคลังผิดพลาด
3. **การแจ้งเตือน Error ที่ไม่ชัดเจน:** เมื่อกดบันทึกแล้วไม่ผ่าน ระบบเดิมขึ้นแค่กรอบสีแดงหรือแจ้ง "ข้อมูลไม่ถูกต้อง" แต่ไม่บอกว่าผิดที่ช่องใดและต้องแก้ไขอย่างไร

## สิ่งที่ต้องการจากระบบใหม่:
1. **หน้า Add Product ที่ออกแบบเรียบง่ายและปลอดภัย:** มี Label กำกับถาวรเหนือทุกช่องกรอก, มีดอกจันสีแดง `*` ระบุช่องที่บังคับกรอก, มีสวิตช์เลือกประเภทสินค้าชัดเจน และปุ่ม "บันทึกข้อมูล" ขนาดใหญ่แยกสีชัดเจนจากปุ่ม "ยกเลิก"
2. **หน้า Dashboard ที่สรุปสถานะและแจ้งเตือนวิกฤต:** มีการ์ดแสดงจำนวนรายการสินค้าทั้งหมด, มูลค่ารวม, และตารางสินค้าใกล้หมด (<= 5 ชิ้น) พร้อมแถบสีเตือนเพื่อเตรียมสั่งเติมสต็อกได้ทันท่วงที

## User Journey Map: บันทึกสินค้าเข้าคลังหนึ่งรายการ

| ขั้น | ผู้ใช้ทำอะไร | รู้สึกอย่างไร | จุดสะดุด (Pain / Friction Point) |
| :--- | :--- | :--- | :--- |
| **1 เปิดระบบ** | เปิดเบราว์เซอร์เข้าสู่ระบบด้วย Username/Password ที่หน้า Login | กังวลเล็กน้อย กลัวจำรหัสผ่านไม่ได้ | ช่องกรอกไม่มีปุ่มกดดูรหัสผ่าน (Show Password) ทำให้พิมพ์ผิดซ้ำและโดนล็อกบัญชี |
| **2 หาเมนูที่ใช้บันทึก** | มองหาปุ่มหรือเมนูสำหรับ "เพิ่มสินค้าใหม่" บนแถบนำทางหลัก | รีบเร่ง อยากเริ่มทำงานทันที | เมนูซ่อนอยู่ในเมนูย่อยลึก หรือไอคอนไม่สื่อความหมาย ไม่มีตัวหนังสือบอกชัดเจน |
| **3 กรอกข้อมูลสินค้า** | พิมพ์ชื่อสินค้า, เลือกประเภท (กายภาพ/ดิจิทัล), รหัสสินค้า, หมวดหมู่, จำนวน และราคา | ลังเล กลัวพิมพ์ผิดช่องหรือสับสนประเภทสินค้า | ช่องกรอกไม่มี Label ค้างไว้ (มีแต่ Placeholder พอพิมพ์แล้วข้อความหาย) และไม่มีตัวเลือกว่าสินค้าเป็นไฟล์ดิจิทัลหรือสินค้าจับต้องได้ ทำให้เผลอใส่จำนวนสต็อกให้สินค้าดิจิทัล |
| **4 กดบันทึก** | เลื่อนหน้าจอลงมาหาปุ่มกดยืนยันบันทึกข้อมูลสินค้า | ระมัดระวัง กลัวเผลอกดปุ่มผิด | ปุ่ม "บันทึก" กับปุ่ม "ยกเลิก" วางติดกันและใช้สีเทาเหมือนกัน เสี่ยงกดผิดทำให้ข้อมูลที่เพิ่งพิมพ์หายหมด |
| **5 ตรวจว่าบันทึกสำเร็จ** | รอผลตอบรับจากระบบว่าข้อมูลถูกบันทึกเรียบร้อยหรือไม่ | ต้องการความมั่นใจ โล่งใจ | หน้าจอค้างนิ่ง ไม่ขึ้นแจ้งเตือนชัดเจนว่าบันทึกสำเร็จหรือยัง ทำให้ผู้ใช้กดปุ่มบันทึกซ้ำซ้อนจนเกิดข้อมูลเบิ้ล |

### จุดสะดุดหลักที่ Mockup ต้องแก้ให้ได้:
> **จุดสะดุดในขั้นที่ 3:** ในหน้า **Add Product** ต้องมี **Label ที่มองเห็นได้ถาวรเหนือทุกช่องกรอก** (ไม่ใช่ Placeholder เพียงอย่างเดียว) พร้อมเครื่องหมาย `*` ที่ช่องบังคับ และมี **Radio Button / Segmented Control ให้เลือกชนิดสินค้า (สินค้าจับต้องได้ [Physical] หรือไฟล์ดิจิทัล [Digital])** อย่างชัดเจน โดยถ้าเลือกไฟล์ดิจิทัล ระบบจะปรับช่องจำนวนเป็น "ไม่จำกัด (N/A)" และแสดงช่องอัปโหลด/ใส่ลิงก์ไฟล์แทนทันที
