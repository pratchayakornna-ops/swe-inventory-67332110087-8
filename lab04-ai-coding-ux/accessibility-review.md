# Accessibility Review & Usability Checklist - Lab 04

เอกสารตรวจสอบการออกแบบ UI Mockup ตามมาตรฐานการเข้าถึง WCAG 2.1 ระดับ AA และหลักการออกแบบ Usability

## 1. ตารางตรวจสอบ Accessibility Checklist

| รายการตรวจ | ผ่าน หรือ ไม่ผ่าน | สิ่งที่แก้ / ข้อสังเกต |
| :--- | :---: | :--- |
| **1. ข้อความหลักบนพื้นขาว contrast อย่างน้อย 4.5 ต่อ 1** | **ผ่าน** | ใช้สีข้อความหลัก `#111827` บนพื้นหลังสีขาว `#FFFFFF` ซึ่งมีค่า Contrast Ratio สูงถึง **15.8:1** (ผ่านเกณฑ์ WCAG AA ที่กำหนดขั้นต่ำ 4.5:1 สำหรับ Body Text และ 3:1 สำหรับ Large Text อย่างสมบูรณ์) |
| **2. ปุ่มหลัก (Primary Button) มี contrast เพียงพอ** | **ผ่าน** | ปุ่มหลักใช้สีพื้นหลัง `#1E40AF` (Deep Blue) ตัวอักษรสีขาว `#FFFFFF` มีค่า Contrast Ratio **8.5:1** ชัดเจน มองเห็นได้ง่าย แม้ในสภาพแสงจ้าของคลังสินค้า |
| **3. ทุกช่องกรอกมี label ที่มองเห็นได้ถาวร** | **ผ่าน** | แก้ไขจากแบบร่างเดิมของ AI ที่ใช้แค่ Placeholder โดยปรับให้มี **Visible Label กำกับอยู่เหนือทุก Input Field ถาวร** แม้ผู้ใช้จะพิมพ์ข้อความลงไปแล้วก็ยังเห็นชื่อฟิลด์อยู่ |
| **4. ช่องที่บังคับกรอกมีสัญลักษณ์ชัดเจน** | **ผ่าน** | ทุกฟิลด์ที่เป็น Required Field (ชื่อ, รหัส, ประเภท, ราคา, จำนวน) มีเครื่องหมายดอกจันสีแดง `*` กำกับอย่างชัดเจน พร้อมข้อความช่วยเหลือ (Helper Text) ด้านล่าง |
| **5. Error ไม่ได้ใช้สีเพียงอย่างเดียว มีไอคอนและข้อความด้วย** | **ผ่าน** | การแจ้งเตือน Error และ Warning สต็อกต่ำ ไม่ได้ใช้เพียงขอบสีแดงหรือสีส้ม แต่มีไอคอนเครื่องหมายตกใจ `[!]` / `⚠️` นำหน้า พร้อมข้อความอธิบายสาเหตุและวิธีแก้ไขปัญหาแบบ Actionable |
| **6. ลำดับการกด Tab เรียงบนลงล่าง ซ้ายไปขวา** | **ผ่าน** | กำหนด Tab Index ตามลำดับโฟกัสที่เป็นธรรมชาติของฟอร์ม เริ่มจากประเภทสินค้า -> รหัสสินค้า -> ชื่อสินค้า -> หมวดหมู่ -> จำนวน -> ราคา -> ปุ่มยกเลิก -> ปุ่มบันทึก |
| **7. ปุ่มมีชื่อบอกหน้าที่ชัดเจน ไม่ใช่แค่ OK หรือกากบาท** | **ผ่าน** | ใช้ชื่อปุ่มที่ระบุ Action ชัดเจน เช่น `[ 💾 บันทึกสินค้า (Save Product) ]` และ `[ ยกเลิก (Cancel) ]` หรือในตารางใช้ `[ + เติมสต็อก ]` แทนที่จะเป็นคำคลุมเครืออย่าง "ตกลง" หรือ "OK" |

## 2. จุดที่ AI ทำพลาดและได้รับการแก้ไขโดยมนุษย์ (อย่างน้อย 2 จุดตามเกณฑ์ Rubric)

### จุดที่ 1: AI ใช้ Placeholder แทน Label ถาวรในฟอร์ม Add Product
- **สิ่งที่ AI สร้างมาตอนแรก:** ในร่างแรกที่ AI ให้มา AI สร้างช่อง Input โดยใส่ข้อความตัวอย่างไว้ข้างในช่อง (Placeholder) เช่น `<input placeholder="ชื่อสินค้า">` โดยไม่มี `<label>` เหนือช่อง
- **ผลกระทบด้าน Accessibility & Usability:** พนักงานคลังสินค้าที่มีทักษะเทคโนโลยีระดับ 2/5 เมื่อคลิกพิมพ์ชื่อสินค้า ข้อความ placeholder จะหายไป ทำให้เกิดความสับสนและจำไม่ได้ว่ากำลังกรอกฟิลด์อะไร (เสี่ยงกรอกสลับช่องระหว่างราคาและจำนวน) อีกทั้ง Screen Reader ของผู้พิการทางสายตาจะไม่สามารถอ่านชื่อฟิลด์ได้อย่างถูกต้อง
- **สิ่งที่แก้ไข:** เพิ่ม `<label>` ที่มองเห็นได้ถาวรเหนือทุกช่องกรอก พร้อมใส่ตัวเลขกำกับลำดับขั้นตอน 1, 2, 3, 4, 5 และคง Placeholder ไว้เฉพาะสำหรับยกตัวอย่างรูปแบบข้อความเท่านั้น

---

### จุดที่ 2: AI ใช้สีเทาอ่อน `#9CA3AF` ในข้อความคำอธิบาย ทำให้ Contrast ไม่ผ่านเกณฑ์
- **สิ่งที่ AI สร้างมาตอนแรก:** AI แนะนำให้ใช้สีเทา `#9CA3AF` บนพื้นหลังสีขาวสำหรับ Helper text (ข้อความแนะนำตัวอย่าง เช่น "ตัวอย่าง: HW-xxxx") เพื่อให้ดูโมเดิร์น
- **ผลกระทบด้าน Accessibility:** สี `#9CA3AF` บนพื้นขาวมี Contrast Ratio เพียง **2.8:1** ซึ่ง **ไม่ผ่านเกณฑ์ WCAG AA (ต่ำกว่า 4.5:1)** ทำให้พนักงานคลังสินค้าที่มีอายุ หรือใช้งานบนหน้าจอคอมพิวเตอร์เก่าในคลังสินค้ามองเห็นตัวหนังสือเลือนรางมากจนอ่านไม่ออก
- **สิ่งที่แก้ไข:** ปรับเปลี่ยนชุดสีของ Helper text และคำเตือนรองมาใช้สี `#4B5563` (Contrast 7.1:1) หรือ `#111827` เพื่อให้อ่านง่าย คมชัด และผ่านเกณฑ์ WCAG AA ทุกจุด

### จุดที่ 3 (จุดเพิ่มเติม): AI มองข้ามความแตกต่างของสินค้า 2 ชนิด (Physical vs Digital)
- **สิ่งที่ AI สร้างมาตอนแรก:** AI ออกแบบหน้า Add Product เสมือนว่าสินค้าทุกตัวในคลังมีลักษณะเหมือนกัน โดยบังคับกรอก "จำนวนสต็อก (Quantity)" เสมอ
- **ผลกระทบด้าน Business Logic & Usability:** สถาปัตยกรรมของระบบตามข้อกำหนดระบุว่า ระบบต้องรองรับทั้งสินค้าที่จับต้องได้และสินค้าดิจิทัล (ไฟล์/License) ซึ่งสินค้าดิจิทัลไม่มีจำนวนสต็อกให้นับ หากปล่อยตามที่ AI ทำ พนักงานจะต้องใส่ตัวเลขสมมติ ทำให้รายงานสต็อกคลังผิดเพี้ยน และไม่มีช่องสำหรับแนบไฟล์/ลิงก์ดาวน์โหลด
- **สิ่งที่แก้ไข:** เพิ่ม Segmented Control ให้เลือกชนิดสินค้าตั้งแต่ต้น หากเลือกสินค้าดิจิทัล ระบบจะ Disable ช่องจำนวนสต็อกอัตโนมัติ และเปิดฟิลด์อัปโหลดไฟล์/ลิงก์ URL ขึ้นมาแทน ทำให้ระบบตอบโจทย์การใช้งานจริง
