# AI-Generated Text Wireframes (ASCII Layout) - Lab 04

เอกสารนี้รวบรวมแบบร่างโครงสร้างหน้าจอ (ASCII Wireframe) ทั้ง 3 หน้าของระบบ Inventory Management ซึ่งสร้างขึ้นโดยอ้างอิงจาก Persona "สมชาย มั่นคงสต็อก" (ทักษะเทคโนโลยี 2/5, ใช้งาน PC เป็นหลัก) ตามข้อกำหนด Usability และ Accessibility (WCAG 2.1 AA)

---

## 1. หน้าเข้าสู่ระบบ (Login Screen)

### Prompt ที่ใช้สั่ง AI:
```text
ช่วยออกแบบ text wireframe (ASCII layout) สำหรับ "หน้า Login" ของระบบ Inventory Management
กลุ่มผู้ใช้: พนักงานคลังสินค้า ทักษะเทคโนโลยีระดับ 2/5 ใช้อุปกรณ์ PC และจอแสดงผลตั้งโต๊ะเป็นหลัก

ข้อกำหนด Usability:
- ฟิลด์ที่ต้องมี: ชื่อผู้ใช้งาน (Username)*, รหัสผ่าน (Password)*, ตัวเลือกจดจำการเข้าสู่ระบบ (Remember Me)
- ปุ่มหลัก: "เข้าสู่ระบบ" (Primary Button เด่นชัด สีน้ำเงินเข้ม #1E40AF)
- แสดง State ครบถ้วน: ข้อความเตือนเมื่อกรอกผิด (Inline Validation Error ใต้ฟิลด์) พร้อมไอคอนเตือน และปุ่มแสดง/ซ่อนรหัสผ่าน (Show/Hide Password toggle)

ข้อกำหนด Accessibility:
- ทุกฟิลด์มี Visible Label ถาวรด้านบน ไม่ใช่ใช้แค่ Placeholder
- Error message ต้องอธิบายวิธีแก้ไขอย่างชัดเจน ไม่ใช่แค่แจ้งว่าผิดพลาด
- ลำดับ Tab Index เรียงจากบนลงล่างอย่างเป็นธรรมชาติ

ขอผลเป็น ASCII layout พร้อมคำอธิบาย Usability/Accessibility
```

### คำอธิบาย Usability & Accessibility:
- **Visible Label:** มีข้อความกำกับชื่อฟิลด์ชัดเจน ไม่หายไปเมื่อเริ่มพิมพ์ ป้องกันความสับสน
- **Show/Hide Password Toggle `[o]`:** ช่วยให้พนักงานที่มีทักษะเทคโนโลยี 2/5 สามารถตรวจสอบตัวอักษรที่พิมพ์ได้ ลดอัตราการพิมพ์ผิดจนบัญชีถูกระงับ
- **Actionable Error Feedback:** ไม่ได้บอกแค่ว่า "ผิดพลาด" แต่แนะนำว่า "กรุณาตรวจสอบแป้นพิมพ์ Caps Lock"
- **Primary Button:** ปุ่มเข้าสู่ระบบมีขนาดใหญ่ กว้างเต็มการ์ด เพื่อให้คลิกหรือแตะได้ง่าย

## 2. หน้าแดชบอร์ดภาพรวมคลังสินค้า (Dashboard Screen)

### Prompt ที่ใช้สั่ง AI:
```text
ช่วยออกแบบ text wireframe (ASCII layout) สำหรับ "หน้า Dashboard" ของระบบ Inventory Management
กลุ่มผู้ใช้: พนักงานคลังสินค้าและหัวหน้างาน ทักษะเทคโนโลยี 2/5 ใช้งาน PC

ข้อกำหนด Usability:
- แสดงการ์ดสรุปยอดสำคัญ: จำนวนสินค้าทั้งหมด (ชิ้น/รายการ), มูลค่ารวมในคลัง (บาท), สินค้าสต็อกต่ำ/ใกล้หมด (รายการ)
- ตารางเตือนสินค้าสต็อกต่ำ (Low Stock Alert <= 5 ชิ้น) และแสดงแยกประเภทชัดเจน (Physical vs Digital)
- เมนูนำทาง (Navigation Bar) ด้านบนพร้อมปุ่มทางลัด "เพิ่มสินค้าใหม่" (Add Product) ที่มองเห็นทันที

ข้อกำหนด Accessibility:
- Contrast สีผ่านเกณฑ์ WCAG AA (#1E40AF สำหรับเมนูหลัก, #B45309 สำหรับ Warning สต็อกต่ำ)
- ใช้ข้อความและสัญลักษณ์คู่กัน (ไม่ใช้สีแดง/ส้มอย่างเดียวในการสื่อความหมาย มี Badge ข้อความกำกับชัดเจน)
- ตารางมี Header กำกับทุกคอลัมน์
```

### คำอธิบาย Usability & Accessibility:
- **ปุ่มทางลัดชัดเจน:** ปุ่ม `[+ เพิ่มสินค้าใหม่]` วางอยู่มุมขวาบนเด่นชัด พนักงานไม่ต้องหาในเมนูย่อย
- **แยกความแตกต่าง 2 ชนิดสินค้า:** แสดงการ์ดสรุปสินค้ากายภาพและดิจิทัลแยกกัน ทำให้พนักงานไม่สับสนเรื่องจำนวนสต็อก
- **Multi-modal Low Stock Warning:** มีทั้งไอคอนเตือน `[!]`, ตัวเลขสต็อก และปุ่มทางลัด `[+ เติมสต็อก]` สามารถคลิกเติมสินค้าได้ทันทีโดยไม่ต้องเปิดหลายหน้า

## 3. หน้าเพิ่มสินค้าใหม่ (Add Product Screen)

### Prompt ที่ใช้สั่ง AI:
```text
ช่วยออกแบบ text wireframe (ASCII layout) สำหรับ "หน้า Add Product" ของระบบ inventory
กลุ่มผู้ใช้: พนักงานคลังทักษะเทคโนโลยีระดับ 2/5 ใช้ PC เป็นหลัก

ข้อกำหนด usability:
- ฟอร์มมีฟิลด์: ชื่อสินค้า*, รหัสสินค้า*, ชนิดสินค้า* (จับต้องได้ หรือไฟล์ดิจิทัล), หมวดหมู่ (dropdown), จำนวน*, ราคา*, อัปโหลดไฟล์/รูป (optional)
- ปุ่ม "บันทึกข้อมูล" (primary) และ "ยกเลิก" (secondary) วางขวาล่าง
- ต้องแสดง state: validation error ใต้ฟิลด์ และ success message หลังบันทึก
- เมื่อเลือกชนิดสินค้าเป็นดิจิทัล ให้ปรับช่องจำนวนเป็น N/A อัตโนมัติและแสดงช่องแนบไฟล์ลิงก์ดาวน์โหลดแทน

ข้อกำหนด accessibility:
- ทุกฟิลด์มี label ที่มองเห็น (ไม่ใช่ placeholder อย่างเดียว)
- required field มีเครื่องหมาย *
- error message อธิบายวิธีแก้ ไม่ใช่แค่ "ผิดพลาด"
- ลำดับ Tab Navigation สมเหตุสมผลจากบนลงล่าง

ขอผลเป็น ASCII layout พร้อมคำอธิบายว่าแต่ละองค์ประกอบช่วย usability อย่างไร
```

### คำอธิบาย Usability & Accessibility:
- **Persistent Labels:** ทุกฟิลด์มีเลขลำดับและชื่อฟิลด์กำกับด้านบนถาวร ไม่ใช้เพียง placeholder ในช่องพิมพ์
- **Dynamic Adaptability สำหรับสินค้า 2 ชนิด:** เมื่อติ๊กเลือก "สินค้าดิจิทัล" ช่องจำนวนสินค้าจะถูก Disable เป็น N/A ทันที เพื่อป้องกันไม่ให้พนักงานกรอกตัวเลขผิดพลาด และเปิดฟิลด์อัปโหลดไฟล์/URL ให้กรอกแทน
- **Inline Actionable Error Messages:** แจ้งเตือนใต้ช่องที่ผิดโดยตรง เช่น "ชื่อสินค้าต้องไม่ว่างเปล่าและมีความยาวอย่างน้อย 3 ตัวอักษร" พร้อมสีและไอคอน `[!]`
- **ปุ่มหลักและปุ่มรองแยกชัดเจน:** ปุ่ม `[ บันทึกสินค้า ]` เป็น Primary Action (สีน้ำเงินเข้มตัวหนังสือขาว) วางด้านขวาสุดตามหลัก Gutenberg Diagram ส่วนปุ่ม `[ ยกเลิก ]` เป็น Secondary Action สีเทาโปร่ง ป้องกันการกดผิด
